# STEP1　顧客価値仮説（売れる）

> IPL標準フロー v1.2／STEP1　（全体像：[01_全体像.md](../01_全体像.md)）

## このSTEPでやること

社内の情報と外部の制約を俯瞰したうえで、**「最初に誰が買うか（一社・一人）」と「なぜ買うか（どんな困りごとが解決するか）」**の仮説を書きます。困りごとは、**死活問題か・まだ見つかっていない課題か・何が足りなくて解決できていないか（ラストワンピース）**の3つの見方で深めます。

## なぜ必要か

- 最初の一人が買わないものは、大きく売れる見込みが薄いからです。「自動車業界」「医療機関」のような大きな括りのままだと、競合も使う場面も見えず、調べることも決まりません。
- 社内にすでにある情報（過去の検討、自社特許、顧客の声）や、規制・社会の動き・トップの発言といった制約を見ないまま仮説を立てると、「すでに社内で検討して見送った」「規制で売れない」といったことに後で気づきます。
- 「あったら便利」程度の困りごとでは、お金は払われません。困りごとの強さと、なぜ今まで解決されていないかまで掘ることで、自社が入る余地が見えます。

## 始める前にそろえるもの

- お題シート、エッジ情報カード（STEP0）
- 手元の情報：依頼者のメモ、社内の技術資料、過去の検討資料、自社特許、営業・顧客の声、最近気になった記事や特許など

STEP1は手元の情報（社内を含む）で立てます。本格的な調査は STEP4・5 に回し、ここでは時間をかけすぎないでください（目安：合計2〜4日。進め方が「小」なら 1-1・1-2 は各30分の簡易版でよい）。

## やり方

### 1-1　社内の情報を俯瞰する（60〜90分）

お題に関わる社内の情報が「どこに・何があるか」を、1枚の表に棚卸しします。中身を読み込むのではなく、まず全体を見渡すことが目的です。

| 見る情報 | 例 | 何が分かるか |
| --- | --- | --- |
| 技術・研究 | 研究報告、技術シーズ一覧、試作・評価の記録 | 使える技術と、その限界 |
| 自社特許・出願 | 自社の関連特許、出願予定 | 守れる範囲の手がかり（詳しくは STEP2） |
| 過去の検討 | 過去の企画書、見送った理由、IPLの過去案件 | 同じ検討のくり返しを防ぐ |
| 顧客・市場の声 | 営業日報、問い合わせ、クレーム、展示会の記録 | 困りごとの手がかり |
| 契約 | 共同研究・ライセンス・秘密保持・独占の契約 | 使えない技術、組めない相手（詳しくは STEP2） |
| 会社の方針 | 中期経営計画、事業部・研究所の方針 | やるべきか（詳しくは STEP3） |

- 「誰に聞けば分かるか」（社内の詳しい人）も書きます。
- [templates/02a_社内情報と外部環境の俯瞰.md](../../templates/02a_社内情報と外部環境の俯瞰.md)
- エージェントに頼めること：棚卸しの項目の抜け探し、社内文書の要約（社内規程で入力してよい範囲で）。自分でやること：どこに何があるかの確認、社内の詳しい人への声かけ。

### 1-2　外部環境と制約を整理する（PESTEL＋トップの発言）（60〜90分）

お題と顧客の困りごとに影響する外部の動きを、**追い風（機会）と制約（向かい風）**に分けて書きます。

| 観点 | 例 |
| --- | --- |
| P 政治 | 政策、補助金、国際関係・輸出管理 |
| E 経済 | 原料価格、為替、景気、顧客業界の投資の動き |
| S 社会 | 人口動態、働き方、消費者の意識 |
| T 技術 | 代替技術の進歩、標準化の動き |
| E 環境 | 脱炭素、資源循環、化学物質の規制 |
| L 法律 | 規制、認証、安全基準、知財制度 |
| トップの発言 | 自社の経営トップの発言（中期経営計画、統合報告書、年頭の挨拶など）、業界・顧客企業のトップの発言 |

- **全部の欄を埋めません。** お題と困りごとに関係し、仮説が変わる項目だけを書きます。
- トップの発言は、会社や業界が進む方向を示す強い制約・追い風になります。発言そのもの（事実：誰が・いつ・どこで・何と言ったか、出典）と、そこからの読み（予想）を分けて書きます。
- 規制や制約は「いつから・どの範囲に」かかるかを書きます。施行前のものは予想として扱います。
- エージェントに頼めること：観点ごとの候補出し、統合報告書・中期経営計画の要約。自分でやること：元の資料での確認（出典の日付と発言者）、仮説に関係する項目の選択。

### 1-3　顧客候補を3〜5つ挙げる（60分）

- STEP0 のお題とエッジ情報カードの「将来の予想（誰に機会が生まれるか）」、1-2 の追い風から始めます。
- 「直接のお客様」と「その先のお客様」を分けて書きます（例：材料なら、直接＝部品メーカー、その先＝完成品メーカーや消費者）。
- BtoB なら会社名・部署・実際に使う人・決裁する人まで、BtoC なら生活の場面・困る頻度・お金を払う人まで書きます。
- エージェントに頼めること：顧客候補の洗い出し、候補の会社の特許・決算資料の要約。自分でやること：どの候補が近いかの判断、元の資料の確認。

### 1-4　ファーストユーザーを1つ決める（30〜60分）

- 候補ごとに、次の5つを1〜5点で仮に付けます：困りごとの強さ／困る頻度／今の手段への不満／予算・決裁権／会いに行ける可能性。
- 点数は**会いに行く順番を決めるためだけ**に使います。買ってくれる証拠ではありません。
- 「この会社（人）に会って話してみたい」と思える理由を1〜3行で書きます。思えないときは、候補の会社の特許・決算資料・求人などを少し調べて、理由が書けるまで深めます。
- [templates/03_困りごとシート_ロジックツリー.md](../../templates/03_困りごとシート_ロジックツリー.md)

### 1-5　今の状態と、ありたい状態を対にする（45分）

- 今のやり方（As-Is）、本当に達成したいこと（To-Be）、その間を妨げているものを書きます。
- 「薄い」「熱に強い」のような機能と、「作業が止まらない」「目立たない」のような得たい成果を分けます。
- 今は何で代用しているか、その手段の費用・損失・不満を書きます。

### 1-6　課題を3つの見方で深める（90〜120分）

1-5 で見えた困りごとを、次の3つの見方で掘り下げます。課題‐解決ロジックツリーとトレードオフを道具として使います。

| 見方 | 問い | 見つけ方の例 | 強い課題のしるし |
| --- | --- | --- | --- |
| ① 死活問題か | 解決しないと、顧客の事業・生活が立ち行かなくなるか | 失注・ライン停止・事故・規制違反・顧客離れにつながるか。今の手段にすでにお金や人を使っているか | 「それなしには過ごせない」。予算がすでにある。期限がある |
| ② まだ見つかっていない課題か | 顧客自身もまだ気づいていない（言葉にしていない）が、これから表に出る課題はないか | 1-2 の変化（規制の強化、技術の世代交代、トップの方針）から先読みする。エッジ情報の「将来の予想」から考える | 変化の時期が読める。先に気づいた人が少ない |
| ③ 何が足りなくて解決できていないか（ラストワンピース） | 解決に向けた取り組みはあるのに、何か1つが足りないために止まっていないか | 誰がどこまで取り組み、どこで止まっているか（特許・論文・製品）。止まっている原因がトレードオフか、技術の壁か、規制か、採算か | 足りない1つがはっきりしている。それを自社が持っている（または持てる）可能性がある |

道具の使い方：

```text
顧客の成果 ─ 妨げる現象 ─ 原因 ─ 解決の原理（案を複数）
                                  └ 止まっている理由（足りない1つ）
```

- ロジックツリーの右端に「止まっている理由（足りない1つ）」を足すと、③が見えやすくなります。
- 「Aを良くするとBが悪くなる」というトレードオフを1〜3個書きます。トレードオフがない課題は、誰かがすぐに解決してしまう可能性があります。
- 上位の言葉に言い換えると、今の用途の外にある用途が見つかることがあります（例：「手」→「人体の一部」→「腕・足・膝」）。
- 3つの見方のうち、少なくとも1つで「強い課題のしるし」が言えるかを確かめます。どれも言えない場合は、課題が弱い可能性があります（1-3 に戻って顧客を変えるか、お題を見直す）。
- [templates/03_困りごとシート_ロジックツリー.md](../../templates/03_困りごとシート_ロジックツリー.md)
- エージェントに頼めること：3つの見方それぞれの候補出し、止まっている理由の仮説出し。自分でやること：どれが本当に強い課題かの判断（STEP7 で顧客に確かめる）。

### 1-7　価値の仮説を1文にする（30分）

> ［顧客］は［場面］で［今の手段］のために［具体的な損失］を受けている。［指標］を［目標値］まで改善できれば、［お金を払う人］が［対価］を払う可能性がある。

- 指標は顧客の判断に直結するものを3つまでにします。
- 1-6 のどの見方（死活問題・まだ見つかっていない課題・ラストワンピース）に当たる課題かを書き添えます。
- 顧客本人に聞いて「そうだ／違う」と答えられる文になっているか確かめます。
- [templates/04_価値仮説_企画骨子.md](../../templates/04_価値仮説_企画骨子.md)

## 発明塾のコツ

- 顧客は「セグメント」ではなく「まず一社・一人」。「会いたい」「提案してみたい」と思えるところまで深めると、ファーストユーザーが自然に「決まる」（発明塾式 企画術3日目）。
- 解決する課題や「不」を明確にし、それなしには過ごせないクリティカルな製品・サービスにする（企業内発明塾 紹介資料）。1-6 の①「死活問題か」はこの考え方による。
- エッジ情報から仮説を立て、課題を「先読み」する（同資料）。1-6 の②「まだ見つかっていない課題」はこの考え方による。
- 誰がどこまで取り組み、どこで止まり、何を見落としているかを読み取り、その壁を自分なら越えられることを示す（情報探索術1日目）。課題はトレードオフまで掘る（技術マーケティングQ&A 1日目）。1-6 の③「ラストワンピース」はこの考え方による（「ラストワンピース」という言葉は本フローでの呼び方。参照した発明塾の資料の中では、この言葉そのものは確認していない）。
- 網羅的な分析から始めず、手元の情報から大胆な仮説を立てる（企画術2日目）。1-1・1-2 は全部を埋めず、仮説が変わる項目だけを書く。

## できあがるもの

- 社内情報と外部環境の俯瞰表、困りごとシート（3つの見方を含む）、課題‐解決ロジックツリー、価値の仮説（1文）

## 次に進む前のチェック（自分で）

- [ ] 社内の過去の検討・自社特許・契約を、少なくとも「あるかないか」確かめた
- [ ] 制約（規制・社会の動き・トップの発言）に出典と日付がある
- [ ] ファーストユーザーが会社名・部署（または具体的な人物像）まで書けている
- [ ] 直接のお客様とその先のお客様を分けて考えた
- [ ] 3つの見方のうち少なくとも1つで「強い課題のしるし」が言える
- [ ] 技術的に難しい理由と、顧客にとって重要な理由を分けて書けている
- [ ] 価値の仮説が、顧客に聞いて賛否を判断できる文になっている

## 困ったら

- 社内の情報がどこにあるか分からない → IPL担当・研究企画・営業企画に「この分野の過去の検討を知っている人」を聞く。
- PESTEL の欄が埋まらない → 埋めなくてよい。お題に関係する制約が1つも思いつかない場合は、規制（L）とトップの発言だけ確認する。
- ファーストユーザーがどうしても1社に決まらない → 2社まで残して STEP2 に進み、STEP7 のヒアリングで決める。
- 3つの見方のどれにも当てはまらない → 課題が弱い可能性がある。顧客を変える（1-3）か、STEP0 のお題を見直す。

## よくある失敗

- フレームワーク（PESTEL など）の欄を埋めることが目的になり、仮説が1つも出ない。
- 特許の「課題」欄に書かれていることを、そのまま顧客の困りごとの証拠にする（出願した会社の見方であって、顧客の声ではありません）。
- トップの発言を、出典や日付を確かめずに引用する（言い換えられた記事を元にしている）。
- 直接のお客様は困っていても、その先のお客様は困っていないことを見落とす。
