# STEP6　構造化・分析

> IPL標準フロー v1.2／STEP6　（全体像：[01_全体像.md](../01_全体像.md)）

## このSTEPでやること

集めた情報をまとめ、**仮説を確かめるための切り口**で分類して表や図にし、表ごとに「だから何か」を書きます。

## なぜ必要か

情報を並べただけでは判断に使えません。また、数え方を間違えると（同じ発明の重複、会社名の表記ゆれなど）結論が変わってしまいます。

## 始める前にそろえるもの

- 情報リスト（STEP5）

## やり方

### 6-1　同じ発明をまとめる（30〜60分）

- 同じ発明を複数の国に出した特許は1つ（ファミリー）として数えます。どちらで数えたかを表に書きます。

### 6-2　会社名をまとめる（30〜60分）

- 子会社名・旧社名・表記ゆれを1つにまとめます（名寄せ）。
- 上位10社ほどは、まとめ方が正しいかIPL担当に確認してもらいます。

### 6-3　仮説に合わせて切り口を決める（30分）

| よく使う切り口 | 確かめられる仮説 |
| --- | --- |
| 課題 × 解決のしかた × 会社 | 勝てる（誰がどの課題をどう解こうとしているか） |
| 顧客の要求 × 設計の条件 | 勝てる・できそう（トレードオフのどちらに寄っているか） |
| 最初の出願年の推移 | 参入の時期、技術の世代交代 |
| 発明者・共同出願先のつながり | 組む相手・ヒアリング先 |
| 権利の範囲と空いているところ | 守れる・出願の方針 |

- 表ごとに「どの仮説IDを確かめるための表か」を書きます。仮説とつながらない表は作りません。

### 6-4　表や図にする（切り口あたり30〜60分）

- 図には、検索式・期間・国・数え方を必ず書きます。他の人が同じ条件で作り直せるようにするためです。
- エージェントに頼めること：集計、表の下書き、グラフの案。

### 6-5　特許の数を読むときの注意を書き添える（10分）

- 最近1年半ほどの出願はまだ公開されていないものが多く、グラフでは「減った」ように見えます。
- 件数が多いことは、強いことと同じではありません。
- 空いているところ（ホワイトスペース）は「見つからなかった」だけで、「自由に使える」でも「ニーズがある」でもありません。

### 6-6　表ごとに「だから何か」を3行書く（表あたり15分）

1. 事実：表から読めること
2. 解釈［予想］：なぜそうなっているか（相手の意図の読み）
3. 仮説への影響：どの仮説IDが強まった・弱まったか

## 発明塾のコツ

- 特許から相手の意図・戦略を先読みし、その先に手を打つ（企業内発明塾 紹介資料）。6-6 の「解釈」がこれに当たります。予想として書き、STEP7 で確かめます。
- 網羅性を求めすぎない（同資料）。表を増やすより、仮説を動かす表を1つ作ります。

## できあがるもの

- 整理表・マップ（数え方と注意書き付き）、表ごとの「だから何か」
- 決まったひな形はありません。表の形は [templates/07_調査計画.md](../../templates/07_調査計画.md) の仮説IDごとに1つ作り、表の下に「だから何か」3行と数え方を書きます。

## 次に進む前のチェック

| 誰が | 確認すること | だめなら |
| --- | --- | --- |
| 自分 | どの表も、確かめる仮説IDが書いてある | 6-3 |
| IPL担当 | 名寄せ・数え方が正しいか。他の人が作り直せるか | 6-1, 6-2 |

## 困ったら

- 表を作ったが「だから何か」が書けない → その表は仮説とつながっていない可能性があります。STEP4 の調査計画に戻って、何を確かめたかったかを見直します。
