# STEP6　構造化・分析

> IPL標準フロー v1.2／STEP6　（全体像：[01_全体像.md](../01_全体像.md)）

## このSTEPでやること

集めた情報をまとめ、**仮説を確かめるための切り口**で分類して表や図にし、表ごとに「だから何か」を書きます。

## なぜ必要か

情報を並べただけでは判断に使えません。また、数え方を間違えると（同じ発明の重複、会社名の表記ゆれなど）結論が変わってしまいます。

## 始める前にそろえるもの

- 情報リスト（STEP5）

## やり方

### 6-1　同じ発明をまとめる（30〜60分）

- 同じ発明を複数の国に出した特許は1つ（ファミリー）として数えます。どちらで数えたかを表に書きます。

### 6-2　会社名をまとめる（30〜60分）

- 子会社名・旧社名・表記ゆれを1つにまとめます（名寄せ）。
- 上位10社ほどは、まとめ方が正しいかIPL担当に確認してもらいます。

### 6-3　仮説に合わせて切り口を決める（30分）

| よく使う切り口 | 確かめられる仮説 |
| --- | --- |
| 課題 × 解決のしかた × 会社 | 勝てる（誰がどの課題をどう解こうとしているか） |
| 顧客の要求 × 設計の条件 | 勝てる・できそう（トレードオフのどちらに寄っているか） |
| 最初の出願年の推移 | 参入の時期、技術の世代交代 |
| 発明者・共同出願先のつながり | 組む相手・ヒアリング先 |
| 権利の範囲と空いているところ | 守れる・出願の方針 |
| 新しく出てきた分類・キーワード（年ごとに初めて現れたもの） | 新しい課題・解決のしかたの兆し（先読み） |
| 2社の得意分野の比較（技術のマップ） | 組む相手・買う相手との重なりと補い合い |
| 他社からの引用と自社からの引用の多さ | 注目されている技術か、自社だけが重視している技術か（引用は公開から時間がかかるため、新しい出願ほど少なく出る） |

- 表ごとに「どの仮説IDを確かめるための表か」を書きます。仮説とつながらない表は作りません。

### 6-4　表や図にする（切り口あたり30〜60分）

- 図には、検索式・期間・国・数え方を必ず書きます。他の人が同じ条件で作り直せるようにするためです。
- エージェントに頼めること：集計、表の下書き、グラフの案。

### 6-5　特許の数を読むときの注意を書き添える（10分）

- 最近1年半ほどの出願はまだ公開されていないものが多く、グラフでは「減った」ように見えます。
- 件数が多いことは、強いことと同じではありません。
- 空いているところ（ホワイトスペース）は「見つからなかった」だけで、「自由に使える」でも「ニーズがある」でもありません。

### 6-6　表ごとに「だから何か」を3行書く（表あたり15分）

1. 事実：表から読めること
2. 解釈［予想］：なぜそうなっているか（相手の意図の読み）
3. 仮説への影響：どの仮説IDが強まった・弱まったか

## 深めるときの観点（任意）

- **観点D　5フォースの見方で出願人を分ける**：特許の出願人（共同出願人を含む）を「顧客になりうる会社／競合／パートナー（組む候補）」に分けて整理し、5つの力（今の競合、新しく入ってくる会社、代わりのもの、買い手の力、売り手の力）のどこに当たるかを見ます。競合がはっきりしない、価格が厳しい業界、といったときに使います。名寄せ（6-2）をしてから分けます。
- [templates/04a_競合と自社の分析.md](../../templates/04a_競合と自社の分析.md)

### 観点H　トレンド分析（人・技術・市場・課題・解決手段）

- **使うとき**：母集団が大きい（目安：数百件以上）／分野の動きを時系列で見たい／仮説から決めた切り口だけでは見落としがないか確かめたい。
- **共通のルール**（どの切り口でも守る）：
  1. 母集団の決め方（検索式・期間・国）を記録する。
  2. ファミリー単位で数える。出願人は名寄せしてから数える。
  3. 直近1年半程度は未公開分があり少なく出るため、除くか注記する。
  4. 「量（件数）」と「伸び（年ごとの件数の傾き）」の両方を見る。データ点が少ない（5年分など）ときの傾きは参考程度にする。
  5. 伸びていることは機会の証拠にはならない（すでに多くの会社が参入している可能性がある）。伸びは「勝てる・儲かる」の参考情報として仮説検証シートに書き、エッジ情報（少数でも意外なもの）と使い分ける。

| 切り口 | 何を数えるか | やり方 | つながる基準 |
| --- | --- | --- | --- |
| 技術 | 特許分類、またはトピック（文章から自動で作ったまとまり）ごとの件数 | 量と伸びで4つに分ける：量が多く伸びている＝成長／量は少ないが伸びている＝新興（機会の候補）／量が多く伸びていない＝成熟／量が少なく伸びていない＝停滞または空白の候補 | 勝てる |
| 課題 | 公報の「課題」の記載 | AIで課題を抽出して分類し、年ごとの変化（課題の移り変わり）を見る。顧客の声ではないので参考扱い | 売れる（参考） |
| 解決手段 | 公報の「解決手段」の記載 | 課題 × 解決手段の表を時期で比べ、解決手段がまだ少ない課題（ラストワンピースの候補）を探す | 勝てる |
| 人 | 出願人（名寄せ後）、発明者、共同出願 | 新しく参入した会社、発明者の移動、共同出願のつながりを見る。顧客・競合・パートナーに分ける（観点D） | 勝てる、組む相手 |
| 市場 | ファミリーの出願国、公報に書かれた用途 | 出願国の推移から、どの市場を重視しているかを推し量る（代わりの指標）。用途の記載の推移を、市場の統計と照らし合わせる | 儲かる |

- **AIの使い方**：
  - 公報の文章からトピックを作る（トピックモデル）、課題・解決手段・用途を抽出して分類する、件数の表から傾きを計算する、といった作業をエージェントや分析ツールに手伝わせてよい。
  - トピックに名前を付けるときは、トピックのキーワード一覧をAIに渡して名前の案を出させ、**人が代表的な公報を読んで確かめる**（名前の付け方で解釈が変わるため）。
  - 抽出・分類の結果はランクB以下として扱い、件数の多い分類や判断に効く分類は、人がサンプルを読んで確かめる。
- [templates/08a_トレンド分析.md](../../templates/08a_トレンド分析.md)

## 発明塾のコツ

- 特許から相手の意図・戦略を先読みし、その先に手を打つ（企業内発明塾 紹介資料）。6-6 の「解釈」がこれに当たります。予想として書き、STEP7 で確かめます。
- 網羅性を求めすぎない（同資料）。表を増やすより、仮説を動かす表を1つ作ります。

## できあがるもの

- 整理表・マップ（数え方と注意書き付き）、表ごとの「だから何か」
- 決まったひな形はありません。表の形は [templates/07_調査計画.md](../../templates/07_調査計画.md) の仮説IDごとに1つ作り、表の下に「だから何か」3行と数え方を書きます。

## 次に進む前のチェック

| 誰が | 確認すること | だめなら |
| --- | --- | --- |
| 自分 | どの表も、確かめる仮説IDが書いてある | 6-3 |
| IPL担当 | 名寄せ・数え方が正しいか。他の人が作り直せるか | 6-1, 6-2 |

## 困ったら

- 表を作ったが「だから何か」が書けない → その表は仮説とつながっていない可能性があります。STEP4 の調査計画に戻って、何を確かめたかったかを見直します。
