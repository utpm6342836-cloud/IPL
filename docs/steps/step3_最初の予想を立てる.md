# Step 3　最初の予想を立てる

> IPL標準フロー v1.0／Step 3　（全体像：[00_全体像.md](../00_全体像.md)）

## 目的

分かっている範囲で企画の骨子と事業の予想を先に書き、「分かっていること／分かっていないこと」と、それぞれの予想が崩れる条件をはっきりさせる。

## 始める条件

- 困りごとシートと課題‐解決ロジックツリー（Step 2）がある。

## 言葉の意味

- 予想（仮説）：今の時点での見込み。調べた結果で変わってよい。
- 崩れる条件：何が分かったら予想が変わるか。
- MVP（Minimum Viable Product）：顧客価値を確かめるのに必要な最小限の構成。

## 手順

### 3-1　企画骨子の5項目を、空欄があってもまず書く（60分）

| 項目 | 書くこと |
| --- | --- |
| ① 顧客価値の予想 | 他では解決できない課題／他では提供できない価値は何か |
| ② 最小限の構成（MVP） | 価値を届けるのに最低限必要な要素は何か |
| ③ ファーストユーザー | まず誰が買うか（会社名・人名まで） |
| ④ 話を聞くための準備物 | 提案書、スケッチ、比較サンプル、原理試作など |
| ⑤ なぜ自分たちがやるのか | どんな背景・経緯でこの企画に行き着いたか |

- 5項目が互いに矛盾しないように書き直す。1つを変えたら他の4つも見直す。
- ひな形：[templates/04_企画骨子_事業の予想シート.md](../../templates/04_企画骨子_事業の予想シート.md)

### 3-2　価値の予想を1文にする（30分）

> ［顧客］は［場面］で［今の手段］のために［具体的な損失］を受けている。［指標］を［目標値］まで改善できれば、［お金を払う人］が［対価］を負担する可能性がある。

- 指標（KPI）は顧客の判断に直結するものを最大3つに絞る。
- 目標値が顧客の実測か、こちらの予想かを書き分ける。
- 顧客本人に聞いて「そうだ／違う」が判断できる文になっているかを確かめる。

### 3-3　6つの観点で予想を書く（60分）

| 観点 | 確かめる質問 | 主に使う情報 |
| --- | --- | --- |
| 売れる | お客様は本当に困っているか。お金を払ってでも解決したいか | 聞き取り、論文、規制の動き |
| 勝てる | 今の技術や競合では、なぜ解決できないのか | 特許（課題と解決手段）、論文、製品情報 |
| 儲かる | 市場の大きさ・価格・参入のしにくさは十分か | 市場レポート、決算資料、有価証券報告書 |
| できる | 自社の技術・設備・規制対応で作れるか | 社内の技術情報、自社特許 |
| 守れる | 特許を取れる余地はあるか。他社の特許に邪魔されないか | 先行技術の調査、他社特許の予備確認、裁判情報 |
| やるべき | 会社の中期計画や目指す姿と合っているか | 統合報告書、中期経営計画 |

- いきなり ○△× を付けない。まず「予想」「状態（事実／予想／未確認）」「根拠」「崩れる条件」を書く。
- Quick の案件では「勝てる」「守れる」の2つだけでもよい。

### 3-4　「なぜ他の人はやっていないか」を書く（30分）

- 少し思いつく程度のことは、たいてい誰かがやっている。他の人が気づいていない、または手を付けていない理由を予想する（技術的な壁、規制、採算、組織の事情など）。
- その理由を自社なら越えられる、と言える根拠があるかを書く。なければ「未確認」。

### 3-5　「差別化」ではなく「独占」の形を考える（30分）

- 他の会社でもよいなら価格競争になる。顧客が「この会社から買わなければならない理由」を書く。
- 特許・営業秘密・顧客認証・供給網・データなど、まねされにくい仕組みの候補を挙げる。知財の戦略を企画の最初から組み込む。

### 3-6　予想に ID を付ける（15分）

- H1, H2 … の ID を付ける。Step 4 の調査計画、Step 7 の予想の記録で同じ ID を使う。

## 発明塾の使いどころ

- 企画の骨子は5つのポイントに沿って言語化する。企画書は自分が確信を得るために作るもので、まとまってから書くのではなく、まず書いて、書きながら詰める（企画術1日目）。
- 「誰が買うか（ファーストユーザー）」「なぜ買うか（顧客価値）」「なぜあなたから買わなければならないか（独占）」の3つを徹底し、「売れる」「勝てる」「儲かる」企画に落とし込む（企業内発明塾 紹介資料）。
- 他の人が気づいていない・手掛けていない理由まで考え、それを越えてこそ企画になる（企業内発明塾 紹介資料）。
- アイデアはそもそも未熟なものなので、すぐに評価せず「育てる」（企業内発明塾 紹介資料）。このステップで○△×を急がないのはそのため。

## できあがるもの

- 企画骨子（5項目）
- 事業の予想シート（6観点、各観点に崩れる条件、ID付き）

## チェックポイント

| 確認する人 | 確認すること | だめなら |
| --- | --- | --- |
| 担当リーダー | すべての観点に「崩れる条件」があるか。価値の予想が、顧客に聞いて賛否を判断できる文になっているか | Step 2 に戻る |

## よくある失敗

- 「市場が伸びる」「高付加価値だから儲かる」を予想の根拠にする。
- 6観点を全部「高」で埋めてしまい、何を調べればよいかが分からなくなる。
- 5項目のうち③ファーストユーザーを空欄のまま進める。
