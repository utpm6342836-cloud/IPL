# STEP2　事業仮説（勝てる・儲かる）

> IPL標準フロー v1.2／STEP2　（全体像：[01_全体像.md](../01_全体像.md)）

## このSTEPでやること

STEP1の「売れる」に続けて、**競合と業界の力関係（5フォース）**と**自社の強み・手持ちの資源（4P・特許・契約・社内資源）**を整理し、**「勝てる（守れるを含む）」「儲かる」**の仮説を書きます。あわせて「できそう（自社で作れるか）」も確かめ、SWOT でまとめて、それぞれの仮説に「何が分かったら崩れるか」を書きます。

## なぜ必要か

顧客が困っていても、他社がすでに解決していたり、業界の力関係で利益が出なかったり、自社で作れなかったり、契約で使えない技術だったりすれば事業になりません。どこが一番あやしいかを先に書いておくと、STEP3 で確かめる仮説を選びやすくなります。

## 始める前にそろえるもの

- STEP1 の価値の仮説、ファーストユーザー、課題（3つの見方）、社内情報と外部環境の俯瞰表
- 手元の情報（社内の技術資料、自社特許、契約の一覧、中期計画など）。本格的な調査は STEP4 以降で行います。

目安：合計2〜3日。進め方が「小」なら 2-2・2-3・2-7 は各30分の簡易版でよい。

## やり方

### 2-1　企画の骨子を、空欄があってもまず書く（60分）

| 項目 | 書くこと |
| --- | --- |
| ① 顧客価値の仮説 | STEP1 の1文 |
| ② 最小限の構成 | 価値を届けるのに最低限必要なもの（MVP） |
| ③ ファーストユーザー | STEP1 で決めた一社・一人 |
| ④ 話を聞くための準備物 | 提案書、スケッチ、比較サンプル、試作など |
| ⑤ なぜ自分たちがやるのか | どんな背景・経緯でここに行き着いたか |

- 5つが互いに矛盾しないように書き直します。1つを変えたら、ほかも見直します。
- [templates/04_価値仮説_企画骨子.md](../../templates/04_価値仮説_企画骨子.md)

### 2-2　競合と業界の力関係を見る（5フォース）（60〜90分）

STEP1 のファーストユーザーと課題から見て、次の5つの力を書きます。

| 力 | 問い | 例 |
| --- | --- | --- |
| 今の競合 | 同じ課題を、誰がどの手段で解こうとしているか | 同業他社、他の原理の製品 |
| 新しく入ってくる会社 | 誰が入ってきそうか。入りやすいか | 異業種、スタートアップ、顧客自身の内製 |
| 代わりのもの | 別のやり方で同じ成果が得られないか | 手作業、外注、何もしない |
| 買い手の力 | 顧客は価格を強く下げられるか。乗り換えやすいか | 顧客が少数の大手、複数社購買 |
| 売り手の力 | 原料・部品の供給元は強いか | 特定の供給元への依存 |

- 競合は「同じ技術の会社」だけではありません。顧客が今使っている方法、何もしないという選択まで含めます。
- 全部を同じ深さで書かず、利益や勝ち負けに一番効きそうな力に印を付けます。
- 1-6 の「ラストワンピース」で見た「止まっている取り組み」が、誰のものかもここで書きます。
- [templates/04a_競合と自社の分析.md](../../templates/04a_競合と自社の分析.md)
- エージェントに頼めること：5つの力ごとの候補出し、競合の特許・決算資料の要約。自分でやること：元の資料での確認、どの力が効くかの判断。

### 2-3　自社の強みと手持ちの資源を整理する（4P・特許・契約・社内資源）（60〜90分）

| 観点 | 書くこと |
| --- | --- |
| 4P：製品（Product） | 何を提供するか（材料・部品・装置・サービス）。2-1 の最小限の構成とつなげる |
| 4P：価格（Price） | どのくらいの値段なら成り立つか（仮でよい） |
| 4P：販路（Place） | どこを通して届けるか（直販・代理店・顧客との既存の取引） |
| 4P：伝え方（Promotion） | 誰に・どう知ってもらうか（技術営業、展示会、共同開発） |
| 特許・出願 | 自社の関連特許、出願の予定、出願の余地がありそうなところ |
| 契約 | 共同研究の成果の帰属、ライセンス（受けている・出している）、独占・競業避止、秘密保持で使えない情報 |
| 社内資源 | 設備、人（キーパーソン）、データ、顧客との関係、品質保証の体制 |

- 4P は、この段階では「提供の形の仮説」として書きます。決まっていなくてかまいません。
- **契約は見落としやすい制約です。** 共同研究の成果を自社だけでは使えない、ライセンス先と競合する、といったことがあれば、勝てる・できそうの仮説が変わります。分からない場合は知財部門・法務に確認します。
- 1-1 の棚卸しで見つけた情報を、ここで中身まで見ます。

### 2-4　「勝てる」を書く（45分）

- 今の技術や競合では、なぜ解決できないのか（2-2 を使う）。
- **なぜ他の人はまだやっていないのか**（技術の壁、規制、採算、組織の事情など）。それを自社なら越えられる理由。
- **ラストワンピースを自社が持っているか**：1-6 の③で見た「足りない1つ」を、自社の技術・特許・設備・顧客との関係（2-3）で埋められるか。
- **守れるか**：顧客が「この会社から買わなければならない理由」を作れるか。特許・ノウハウ・データ・顧客認証・供給網など、まねされにくい仕組みの候補を挙げます。
- 「自社が特許を取れる余地がある」と「他社の特許を侵害せずに実施できる（FTO）」は別の問題です。FTOはこのフローでは判断しません。

### 2-5　「儲かる」を書く（45分）

- まず1社分の売上：年間の使用量 × 採用率 × 自社の単価（予想でかまいません）。
- 何社に、どのくらいの速さで広がるか。
- 2-2 の買い手・売り手の力が強い場合は、価格や原価にどう効くかを書きます。
- 「市場が伸びている」「高付加価値だから」だけを根拠にしません。
- エージェントに頼めること：競合が反論するとしたら何と言うかの候補出し、1社分の売上の計算式の下書き。自分でやること：数字の前提が妥当かの判断。

### 2-6　「できそう」を書く（30分）

- 図の名前には出ていませんが、自社で作れない・規制を越えられない場合は事業になりません。勝てる・儲かると同じ表に書きます。
- 必要な性能、量産、品質保証、規制・認証、社内の設備と人、外部の協力先。
- 1-2 の制約（規制・トップの方針）と 2-3 の契約が、作る・売ることを妨げないかを確かめます。
- 「技術的にできる」と「期限と予算の中で顧客の認証まで取れる」は別に書きます。

### 2-7　SWOTでまとめ、打ち手の候補を出す（クロスSWOT）（45〜60分）

| | 機会（O）：1-2 の追い風、1-6 の課題 | 脅威（T）：1-2 の制約、2-2 の競合・代わりのもの |
| --- | --- | --- |
| 強み（S）：2-3 | 強みで機会をつかむ打ち手 | 強みで脅威をかわす打ち手 |
| 弱み（W）：2-3 | 弱みを補って機会をつかむ打ち手（組む・買う） | 弱みと脅威が重なる＝避けるべき場面 |

- 各マスの打ち手は1〜3個まで。打ち手ごとに、どの仮説（H1, H2…）に関係するかを書きます。
- SWOT は「一覧を作ること」が目的になりやすいので、**打ち手の候補と仮説につながらない項目は書かなくてよい**です。
- [templates/04a_競合と自社の分析.md](../../templates/04a_競合と自社の分析.md)

### 2-8　仮説ごとに状態・根拠・崩れる条件を書く（45分）

- [templates/05_事業仮説シート.md](../../templates/05_事業仮説シート.md) に、売れる・勝てる・儲かる・できそう の仮説を並べ、ID（H1, H2…）を付けます。
- 各仮説に「状態（事実／予想／未確認）」「根拠（出典）」「崩れる条件」を書きます。
- いきなり ○△× を付けません。今の段階では、ほとんどが「予想」「未確認」で問題ありません。

### 2-9　一番あやしい仮説に印を付ける（15分）

- 崩れたら全体が成り立たなくなる仮説で、根拠が一番弱いものに印を付けます。STEP3 で確かめる仮説を選ぶときの手がかりにし、STEP4 以降はここから調べます。

## 発明塾のコツ

- 企画の骨子は5つのポイントで、まず書き、書きながら詰める（発明塾式 企画術1日目）。
- 「誰が買うか」「なぜ買うか」「なぜあなたから買わなければならないか（独占）」の3つで、売れる・勝てる・儲かる企画に落とし込む。他でもよいなら価格競争になるので、差別化より独占を最初から考え、知財の戦略も企画に組み込む（企業内発明塾 紹介資料）。2-3 で特許・契約を、2-4 で守れるかを書くのはこのため。
- 他の人が気づいていない・手を付けていない理由まで考え、それを越えてこそ企画になる（同資料）。2-4 の「ラストワンピースを自社が持っているか」はこの考え方による。
- アイデアはそもそも未熟なもの。すぐに評価せず育てる（同資料）。○△× を急がないのはこのためです。

## できあがるもの

- 企画骨子（5項目）、競合と自社の分析（5フォース・4P/特許/契約/社内資源・クロスSWOT）、事業仮説シート（ID・崩れる条件付き）

## 次に進む前のチェック

| 誰が | 確認すること | だめなら |
| --- | --- | --- |
| 自分 | 競合に「代わりのもの」「何もしない」を含めた。契約による制約の有無を確かめた | 2-2、2-3 |
| 自分 | すべての仮説に「崩れる条件」がある。一番あやしい仮説に印がある | 2-8 に戻る |

## 困ったら

- 「勝てる」の理由が技術の性能しか書けない → 顧客が切り替えるときの手間、認証、供給の安定、販路など、技術以外の理由も考える（2-3 の 4P・社内資源）。エージェントに「競合が反論するとしたら何と言うか」を聞く。
- 契約の中身が分からない → 知財部門・法務に、関連する共同研究・ライセンス契約の有無を聞く。
- 儲かるの数字がまったく分からない → 「未確認」として、STEP4 で調べる項目にする。

## よくある失敗

- 5フォース・SWOT の表を埋めることが目的になり、仮説や打ち手につながらない。
- 競合を同じ技術の会社だけに限り、代わりのもの（他の原理、手作業、何もしない）を見落とす。
- 共同研究の契約で、成果を自社だけでは使えないことに後で気づく。
