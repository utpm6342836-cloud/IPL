# STEP2　事業仮説（勝てる・儲かる）

> IPL標準フロー v1.2／STEP2　（全体像：[01_全体像.md](../01_全体像.md)）

## このSTEPでやること

STEP1の「売れる」に続けて、**「勝てる（守れるを含む）」「儲かる」**の仮説を書き、あわせて「できそう（自社で作れるか）」も確かめて、それぞれに「何が分かったら崩れるか」を書きます。

## なぜ必要か

顧客が困っていても、他社がすでに解決していたり、利益が出なかったり、自社で作れなかったりすれば事業になりません。どこが一番あやしいかを先に書いておくと、STEP4で何を重点的に調べればよいかが決まります。

## 始める前にそろえるもの

- STEP1 の価値の仮説、ファーストユーザー、ロジックツリー
- 手元の情報（社内の技術資料、自社特許、中期計画など）。本格的な調査は STEP4 以降で行います。

## やり方

### 2-1　企画の骨子を、空欄があってもまず書く（60分）

| 項目 | 書くこと |
| --- | --- |
| ① 顧客価値の仮説 | STEP1 の1文 |
| ② 最小限の構成 | 価値を届けるのに最低限必要なもの（MVP） |
| ③ ファーストユーザー | STEP1 で決めた一社・一人 |
| ④ 話を聞くための準備物 | 提案書、スケッチ、比較サンプル、試作など |
| ⑤ なぜ自分たちがやるのか | どんな背景・経緯でここに行き着いたか |

- 5つが互いに矛盾しないように書き直します。1つを変えたら、ほかも見直します。
- [templates/04_価値仮説_企画骨子.md](../../templates/04_価値仮説_企画骨子.md)

### 2-2　「勝てる」を書く（45分）

- 今の技術や競合では、なぜ解決できないのか。
- **なぜ他の人はまだやっていないのか**（技術の壁、規制、採算、組織の事情など）。それを自社なら越えられる理由。
- **守れるか**：顧客が「この会社から買わなければならない理由」を作れるか。特許・ノウハウ・データ・顧客認証・供給網など、まねされにくい仕組みの候補を挙げます。
- 「自社が特許を取れる余地がある」と「他社の特許を侵害せずに実施できる（FTO）」は別の問題です。FTOはこのフローでは判断しません。

### 2-3　「儲かる」を書く（45分）

- まず1社分の売上：年間の使用量 × 採用率 × 自社の単価（予想でかまいません）。
- 何社に、どのくらいの速さで広がるか。
- 「市場が伸びている」「高付加価値だから」だけを根拠にしません。
- エージェントに頼めること：競合が反論するとしたら何と言うかの候補出し、1社分の売上の計算式の下書き。自分でやること：数字の前提が妥当かの判断。

### 2-4　「できそう」を書く（30分）

- 図の名前には出ていませんが、自社で作れない・規制を越えられない場合は事業になりません。勝てる・儲かると同じ表に書きます。

- 必要な性能、量産、品質保証、規制・認証、社内の設備と人、外部の協力先。
- 「技術的にできる」と「期限と予算の中で顧客の認証まで取れる」は別に書きます。

### 2-5　仮説ごとに状態・根拠・崩れる条件を書く（45分）

- [templates/05_事業仮説シート.md](../../templates/05_事業仮説シート.md) に、売れる・勝てる・儲かる・できそう の仮説を並べ、ID（H1, H2…）を付けます。
- 各仮説に「状態（事実／予想／未確認）」「根拠（出典）」「崩れる条件」を書きます。
- いきなり ○△× を付けません。今の段階では、ほとんどが「予想」「未確認」で問題ありません。

### 2-6　一番あやしい仮説に印を付ける（15分）

- 崩れたら全体が成り立たなくなる仮説で、根拠が一番弱いものに印を付けます。STEP3 で確かめる仮説を選ぶときの手がかりにし、STEP4 以降はここから調べます。

## 発明塾のコツ

- 企画の骨子は5つのポイントで、まず書き、書きながら詰める（発明塾式 企画術1日目）。
- 「誰が買うか」「なぜ買うか」「なぜあなたから買わなければならないか（独占）」の3つで、売れる・勝てる・儲かる企画に落とし込む。他でもよいなら価格競争になるので、差別化より独占を最初から考え、知財の戦略も企画に組み込む（企業内発明塾 紹介資料）。
- 他の人が気づいていない・手を付けていない理由まで考える（同資料）。
- アイデアはそもそも未熟なもの。すぐに評価せず育てる（同資料）。○△× を急がないのはこのためです。

## できあがるもの

- 企画骨子（5項目）、事業仮説シート（ID・崩れる条件付き）

## 次に進む前のチェック

| 誰が | 確認すること | だめなら |
| --- | --- | --- |
| 自分 | すべての仮説に「崩れる条件」がある。一番あやしい仮説に印がある | 2-5 に戻る |

## 困ったら

- 「勝てる」の理由が技術の性能しか書けない → 顧客が切り替えるときの手間、認証、供給の安定など、技術以外の理由も考える。エージェントに「競合が反論するとしたら何と言うか」を聞く。
- 儲かるの数字がまったく分からない → 「未確認」として、STEP4 で調べる項目にする。
