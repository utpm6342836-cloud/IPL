# STEP4　調査設計

> IPL標準フロー v1.2／STEP4　（全体像：[01_全体像.md](../01_全体像.md)）

## このSTEPでやること

「テーマで検索する」のではなく、**「仮説 → 確かめるのに必要な情報 → 調べる場所 → 検索のしかた」**の順で調べ方を決めます。外れている証拠の探し方と、調べるのをやめる条件も先に決めます。

> このフローの調査は、仮説を確かめるための調査（技術動向の調査に近いもの）です。**侵害予防調査（クリアランス）と無効資料調査は扱いません。** 必要になったら知的財産センターに相談してください。

## なぜ必要か

テーマ名のキーワードで検索すると、数千件の特許が出てきて、どれを読めばよいか分からなくなります。仮説から逆算すれば、読む量を減らせます。

## 始める前にそろえるもの

- 調査目的シート（STEP3。決めたいこと、確かめる仮説と順番、Go／やめる条件。IPL担当の確認①済み）
- 仮説検証シート（STEP2、ID付き）

## やり方

### 4-1　仮説ごとに「確かめる問い」と「必要な情報」を書く（仮説あたり15分）

- 仮説検証シートの「B. 調べ方」に、STEP3 で選んだ行ごとに書きます。調べたことが必ずどれかの仮説の検証につながるようにするためです。
- 基準ごとの「確かめる問い」と「必要な情報」の型：

| 基準 | 確かめる問いの例 | 必要な情報の例 | 主な調べ方 |
| --- | --- | --- | --- |
| 売れる | その顧客は、この課題に今お金や人を使っているか。最初にお金を払うのは誰か | 顧客の事業リスク・設備投資・求人、課題に関する顧客の発言、ヒアリングの結果 | 決算資料・統合報告書、ヒアリング（STEP7） |
| 勝てる | 競合・代わりのものは、この課題をどこまで解けているか。自社だけが越えられる壁は何か | 課題×解決手段×出願人の特許、競合製品の仕様、自社の特許・技術 | 特許分析（STEP6）、製品資料、論文 |
| 儲かる | ファーストユーザーと似た課題を持つ顧客は何社あるか。1社分の売上はいくらか。市場の規模・成長率は | 顧客の数・使用量、価格の目安、業界統計・市場レポート（定義・年・地域） | 統計、決算資料、市場レポート、ヒアリング |
| できそう | 必要な性能・量産・認証を、期限と予算の中で越えられるか | 社内の評価結果、規制・認証の要件と期間、契約 | 社内資料、法令・行政の資料、知的財産センター・法務 |

- 目的が出願の戦略・研究テーマ・組む相手探しのときは、[02_4つの基準.md](../02_4つの基準.md) 4章の読み替えに合わせて問いを書きます。

- 例：H2「既存の薄型電極は長時間つけると剥がれる」→ 必要な情報＝既存製品の仕様、剥がれに関する論文、剥がれ対策の特許の出願の動き。
- STEP3 で選んだ仮説だけを、決めた順番で並べます。全部を同じ深さで調べません。

### 4-2　調べる場所を決める（仮説あたり10分）

| 情報 | 主な場所（無料） |
| --- | --- |
| 日本の特許 | J-PlatPat https://www.j-platpat.inpit.go.jp/ |
| 海外の特許・ファミリー | Espacenet https://worldwide.espacenet.com/ ／Google Patents https://patents.google.com/ |
| 論文・研究者 | J-GLOBAL https://jglobal.jst.go.jp/ ／Google Scholar https://scholar.google.com/ |
| 日本の上場企業 | EDINET https://disclosure2.edinet-fsa.go.jp/ ／各社のIRページ |
| 米国の上場企業 | SEC EDGAR https://www.sec.gov/search-filings |
| 規制・統計 | 対象地域の公的機関のサイト（基準日と条件を記録） |
| 顧客の本音 | ヒアリング（STEP7）。公開情報では分からないことが多い |

| 社内の特許データベース | Shareresearch（特許の検索・母集団づくりは基本的にこちら。使い方はIPL担当に聞く） |

### 4-3　検索を3つの層に分ける（30分）

| 層 | 中身 | 例 |
| --- | --- | --- |
| A：顧客の課題・用途 | 何に困っているか | 装着の違和感、品質の安定 |
| B：解決のしかた・技術 | どう解決するか | 接着、伸縮、湿度の制御 |
| C：会社・製品 | 誰がやっているか | 会社名、製品名、提携先 |

- A だけ、B だけ、A×B で件数を比べると、「その技術を別の課題に使っている会社が多い」などが見えることがあります（見えたことは予想として扱います）。

### 4-4　検索の中心を一言にし、検索式を作る（仮説あたり15分＋エージェント）

あなたがやるのは、次の2つだけです。検索式そのものは、エージェント（特許検索支援）に作らせてかまいません。

1. **探したいものを一言で書く**：「［技術分野］に関して、［必須の構成・手段］が、［特徴（状態・関係・処理）］である」。例：「箸に関して、先端と箸置きの磁石が、反発して先端を浮かせる」。仮説の「勝てる」「できそう」を確かめるなら、競合や自社の解決のしかたを、この形で書きます。
2. **漏れの少なさとノイズの少なさの、どちらを重視するかを決める**：

| 確かめたいこと | 重視すること | 理由 |
| --- | --- | --- |
| 誰がどんな課題・解決のしかたに取り組んでいるか（動向） | ノイズの少なさ | 俯瞰できればよく、1件の漏れで判断は変わりにくい |
| 「競合はまだこの課題を解けていない」「この解決のしかたは誰もやっていない」 | 漏れの少なさ | 1件の見落としで結論が逆になる |
| まず近い技術を数件知りたい | どちらでもない（簡易） | 検索式を作り込まなくてよい |

- 検索する前に、ヒットしそうな公報を予想して書きます（どんな出願人が、どんな課題で出していそうか）。予想と違う結果が出たら、仮説か検索式のどちらかがずれています。
- 最初は一言の言葉だけで試しに検索し、件数とノイズの傾向を見てから広げます。
- 一言と、重視することを渡すと、エージェントが、観点ごとの言葉（同義語・広い言葉・狭い言葉・英語）、特許分類の候補、Shareresearch で使う検索式の案、見直しのしかたを返します。
- 特許分類の記号は、エージェントが間違えることがあります。主な記号は、パテントマップガイダンス（PMGS）か J-PlatPat の分類の照会で確かめます。
- 気になる特許の「課題」やトレードオフから、まだ表に出ていない課題を予想し、その言葉で検索するのも有効です。
- エージェントに頼めること：観点ごとの言葉、特許分類の候補、検索式の案と直し方。自分でやること：一言と重視することを決める、分類の記号と検索結果を確かめる。

### 4-5　検索式を確かめる（30分）

- 次の4つが入っているかを見ます：すでに知っている代表的な特許／予備検索で見つけた特許／審査で引用された文献／その分野の主な会社の出願。
- 出てきた中から20件ほど見て、関係ないものの割合を記録します。
- 直す方向（エージェントに見せると、案を出してくれます）：漏れを減らすなら、検索する範囲を広げる（要約→請求項→全文）、上の階層の分類、同義語・広い言葉を足す。ノイズを減らすなら、その逆。
- 外れた公報が、なぜヒットしたかを見ます（どの言葉の組み合わせがノイズを呼んでいるか）。
- 関係するものの割合が高すぎるときは、漏れを疑います。分類で引けてキーワードで引けなかったもの（分類 NOT キーワード）を数件見ます。
- 検索した日、件数、使ったデータベース、検索式を記録します（他の人が作り直せるように）。

### 4-6　外れている証拠の探し方を書く（仮説あたり15分）

- 例：「今の手段で十分」という顧客の声、すでに解決したという他社の製品や特許、失敗した事業の記事、規制で使えない可能性。
- 「特許が見つからない」ときは、秘密にしている・まだ公開されていない（出願から公開まで原則1年半）・検索式の漏れ、のどれかを確かめる方法も書きます。

### 4-7　やめる条件と時間の上限を書く（10分）

- 仮説ごとに「ここまで分かったらやめる」「何時間まで」を書きます。
- [templates/07_調査計画.md](../../templates/07_調査計画.md)

## 深めるときの観点（任意）

- **観点G　外部の制約を確かめる**：STEP1 の観点Bで仮置きした制約（規制・社会の動き・トップの方針）が判断を左右しそうなら、確かめる仮説として調査計画に入れます。調査エージェント（Web調査）に一次情報（法令、行政の資料、統合報告書など）を探させ、出典を人が確かめます。

## 発明塾のコツ

- 課題を先読みして検索する（仮説検索）。特許の課題とトレードオフに注目する（企業内発明塾 紹介資料）。
- 仮説が変わるたびに大きな母集団を作り直すのは、知識と時間が必要（発明塾式 企画術2日目）。本フローでは、仮説を確かめるのに必要な範囲だけ調べ、検索式を記録して作り直しやすくします。

## できあがるもの

- 調査計画（仮説ID・必要な情報・場所・検索式・外れている証拠の探し方・やめる条件・時間の上限）

## 次に進む前のチェック

| 誰が | 確認すること | だめなら |
| --- | --- | --- |
| 自分 | すべての仮説に「外れている証拠の探し方」と「やめる条件」がある | 4-6, 4-7 |
| IPL担当（検索式を使う場合） | 代表的な特許が拾えているか。重視すること（漏れ／ノイズ）と検索式が合っているか | 4-4, 4-5 |

## 困ったら

- 検索結果が多すぎる・少なすぎる → 検索式と件数をエージェントに見せて理由の候補を聞き、IPL担当に確認する。件数の正解はないので、読める件数から逆算して式を絞る。
- 迷ったら → 調査目的（STEP3）と一言に戻る。目的に合わない検索式を「もったいない」と残さない。
