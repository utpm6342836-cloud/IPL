# フロー検証の進め方

> IPL標準フロー v1.1　対象：標準化チーム・IPL担当

「このSTEPで本当に正しいのか」を、思い込みではなく証拠で確かめるための手順。版を改訂するたびに行う。
記録には [templates/14_フロー検証チェックリスト.md](../templates/14_フロー検証チェックリスト.md) を使う。

## 1. 6つの検証

| No | 検証 | 何が分かるか | 誰が | いつ | 本版（v1.1）での状態 |
| --- | --- | --- | --- | --- | --- |
| V1 | 構造チェック | 各STEPに目的・入力・出力・チェック・戻り先・時間・分担がそろっているか。STEP間がつながっているか | 標準化チーム（自動＋目視） | 改訂のたび | 実施済み（3章） |
| V2 | 既存資料との照合 | 発明塾の手法、過去の手順書の要素が抜けていないか | 標準化チーム | 改訂のたび | 実施済み（4章） |
| V3 | 外部の基準との照合 | 公的なIPLの考え方と比べて抜けがないか | 標準化チーム | 年1回 | **未実施**（5章） |
| V4 | 過去案件への当てはめ | 実際の企画・案件に当てはめると、どこが合い、どこが合わないか | IPL担当 | 改訂のたび（1〜2件） | 1件試行（6章） |
| V5 | パイロット運用 | 実際に事業・研究の人が使えるか、時間はどのくらいか | 利用者＋IPL担当 | 2026年度中に2〜3件 | 未実施（7章） |
| V6 | エージェントでの検証 | エージェントが手順書どおりに案内するか | 標準化チーム | エージェント改訂のたび | テスト質問を用意済み |

1つの検証だけで「正しい」とは言えない。V1・V2 は「書き漏れ」を、V3 は「考え方の抜け」を、V4・V5 は「実際の仕事に合うか」を確かめる。最も重いのは V5。

## 2. 改訂の判断基準

| 状況 | 対応 |
| --- | --- |
| V1 で不合格の項目がある | 公開前に必ず直す |
| V3 で、公的な基準にある要素が本フローにない | 入れるか、入れない理由を改訂履歴に書く |
| V4・V5 で、同じSTEPについて2件以上の案件で「合わない」「飛ばした」 | そのSTEPの手順を見直す |
| V5 で、あるSTEPの時間が目安の2倍以上かかった案件が半分以上 | 目安時間かやり方を見直す |
| アンケートで「分かりにくい」（1〜2点）が3割以上 | 言い方・例を見直す |

基準の数字は仮置き。パイロットの件数が少ないうちは、数字よりも中身（何が合わなかったか）で判断する。

- STEPの出力が次のSTEPの入力になっている（依頼シート → 価値の仮説 → 事業仮説シート → 調査計画 → 情報リスト → 整理表 → 仮説の記録 → 判断メモ → ノウハウ集）。
- 戻り先はすべて実在するSTEPを指している。
- 反証を探す手順：STEP3（3-6）、STEP4（4-2 の「−」）、STEP6（6-1〜6-3）。

## 5. V3 外部の基準との照合（未実施）

照合する基準：
- 特許庁「IPランドスケープ実践ガイドブック」（2024年）：https://www.jpo.go.jp/support/example/ip-landscape-guide/ （PDF：https://www.jpo.go.jp/support/example/ip-landscape-guide/document/index/all_guidebook.pdf ）
- 特許庁「経営戦略に資する知財情報分析・活用に関する調査研究」（2020年度）：https://www.jpo.go.jp/support/general/document/chizai-jobobunseki-report/chizai-jobobunseki-document.pdf

本版の作成環境からは特許庁のサイトに接続できなかったため（ネットワークの制限）、**照合していない**。記憶にもとづく推測で埋めることはしていない。

やり方：
1. ガイドブックの「進め方・プロセス」の章で、各段階の名前と中身を書き出す（ページ番号付き）。
2. 本フローのどのSTEPに対応するかを表にする（チェックリストのB欄）。
3. ガイドブックにあって本フローにない要素、逆に本フローにしかない要素を書き出す。
4. ない要素は「入れる／入れない理由を書く」のどちらかにする。
5. あわせて、ガイドブックの「留意点」（例：目的があいまいなまま分析する、件数だけで判断する、などに当たる記載があるか）を、各STEPの「よくある失敗」と照らす。

## 6. V4 過去案件への当てはめ（試行1件）

対象：「米用心棒_企画メモ_260122」（Google ドライブ、手書きメモのPDF。読み取りは文字認識によるため一部不正確な可能性がある）

| STEP | メモにあったもの | 判定 | 手順書から見た不足 |
| --- | --- | --- | --- |
| 0 目的設定 | なし（コンセプトから始まっている） | 合わない | 何を決めるためのメモか、Go／やめる条件が書かれていない。アイデア段階のメモでは STEP0 を後から書く運用もありうる |
| 1 顧客価値仮説 | 解決する課題（米粒の中の卵のふ化、忌避剤の臭い、忌避剤だけ・乾燥剤だけでは不十分）、使う場面（シンク下、まとめ買い） | おおむね合う | 顧客が「米を保存する人」という広い括りで、ファーストユーザー（一人）まで落ちていない。お金を払う人・今の手段への不満の強さは未確認 |
| 2 事業仮説 | 売れる理由、勝てる理由（乾燥剤と忌避剤の空間的分離など）、儲かる理由（リピート、サブスク、通年需要） | よく合う | 「守れる」（特許で独占できるか）と「できそう」（製造・食品衛生の規制）の記載がない。各仮説の崩れる条件がない |
| 3〜6 | なし | 対象外 | まだ調査前の段階 |

この試行から推測されること：
- 共有済みフローの STEP1・2 は、アイデア段階の企画メモの書き方と自然に合っている（売れる・勝てる・儲かるで整理する発想が共通）。
- 一方、メモの段階では STEP0（目的・判断条件）と「守れる」「崩れる条件」が抜けやすい。手順書の STEP0 と STEP2 2-2・2-5 のチェックは、この抜けを補う働きをすると考えられる。
- 1件だけの試行で、しかも IPL 案件として進めたものではないため、フロー全体の妥当性を示すものではない。次は、実際に調査まで進んだ案件（例：「特許分析_セルロースエステル_エーテル」の分析）で STEP3〜5 を当てはめる。

## 7. V5 パイロット運用で測ること

| 指標 | 測り方 | 何の確認か |
| --- | --- | --- |
| STEPごとの所要時間 | 振り返りアンケート | 目安時間が現実的か |
| 飛ばした・軽くしたSTEPと理由 | 同上 | 不要なSTEP、目的別の飛ばし方 |
| 戻った回数と戻り先 | 案件ファイルのチェックポイント記録 | 戻りの矢印が正しいか（F3 の検討） |
| 確認ポイント①②の指摘内容 | IPL担当の記録 | 品質の弱いSTEPはどこか |
| 判断メモの4点（根拠・最大の不確かさ・最小の実験・次の判断日）がそろった割合 | 判断メモ | STEP7 の手順が機能しているか |
| 利用者の分かりやすさ・役立ち度 | アンケート（1〜5） | 書き方が読者に合っているか |
| 1〜2年後の判断の当たり外れ | STEP8 で決めた振り返り日 | フローが良い判断につながったか（最も時間がかかるが最も重要） |

## 8. エージェントに検証役をさせる場合の依頼文（例）

> あなたはIPL標準フローの検証役です。添付の手順書（STEP0〜8）を読み、次の観点で問題点を挙げてください。①あるSTEPの出力が次のSTEPの入力になっていない箇所、②戻り先が足りない箇所、③事業・研究の担当者が一人で読んだときに意味が分からない言葉、④反証を探す手順が抜けている箇所、⑤時間がかかりすぎる手順。各指摘に、手順番号と理由を付けてください。指摘は事実と推測を分けて書いてください。

エージェントの指摘は候補であり、採用するかは標準化チームが決める。
