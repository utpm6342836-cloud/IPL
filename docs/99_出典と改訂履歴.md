### v1.2 追記（2026-11-17）：「必須」と「深めるときの観点」の分離

| 変更 | 内容 | 理由 |
| --- | --- | --- |
| 考え方 | 各STEPの手順を「必須（これだけで次に進める）」と「深めるときの観点（任意）」に分けた。観点はエージェントが状況に応じて1つずつ声をかける | 必須を増やすと前に進まなくなるため。確からしさは検証ループで高める |
| STEP1 | 必須は 1-1 顧客・ファーストユーザー、1-2 困りごと（死活問題かを一度問う）、1-3 価値の仮説の3つ。観点A 社内情報の俯瞰（Microsoft 365 Copilot の活用）、観点B 外部の制約の下調べ（最大3つ、調査エージェントで仮置き）、観点C 課題の3つの見方（死活問題・まだ見つかっていない課題・ラストワンピース）を追加 | 社内・外部の制約や課題の強さという見方は残しつつ、必須にはしない |
| STEP2 | 必須は 2-1 企画骨子、2-2 勝てる（代わりのもの、守れる、契約の技術なら知財部門に確認）、2-3 儲かる・できそう、2-4 崩れる条件の4つ | 同上 |
| 観点の置き場所 | 観点D 5フォース → STEP6（特許の出願人を顧客・競合・パートナーに分ける）／観点E 自社の強みと資源 → STEP7（狙う市場・競合と比べる）／観点F クロスSWOT → STEP7〜8／観点G 外部の制約の確認 → STEP4〜5／会社・部門の目標や金額の目安 → STEP3 で仮置き | 狙う市場や競合がはっきりしてからのほうが、分析の意味が出るため |
| ひな形 | 02a 社内情報と外部環境の俯瞰、04a 競合と自社の分析を「任意」として追加。困りごとシートに課題の3つの見方（任意）を追加 | 観点を使うときの道具として |
