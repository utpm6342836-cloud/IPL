# SharePoint（SPO）サイト構成案

目的：標準フローを人が読む場所と、Copilot Studio エージェントが読む場所を同じにして、二重管理を避ける。

## 1. サイトの構成

| 種類 | 名前 | 中身 | 元ファイル |
| --- | --- | --- | --- |
| ページ | ホーム | 10ステップの全体図、「今どこにいるか分からない人はここから」、エージェントへのリンク | docs/00_全体像.md |
| ページ | Step 0〜9（10ページ） | 個別手順書。1ステップ1ページ | docs/steps/*.md |
| ページ | 発明塾の手法との対応 | 対応表 | docs/90_発明塾手法との対応.md |
| ページ | よくある質問 | エージェントのテスト質問から作る | copilot-studio/テスト質問.md |
| ドキュメントライブラリ | ひな形 | 依頼シート〜ノウハウ集（Word／Excel 版も置く） | templates/ |

## 2. 運用のルール

- 正本は1つにする。このリポジトリ（Markdown）を正本にし、SharePoint のページとエージェント用ナレッジは正本から作る。逆に SharePoint で直接直した場合は、正本にも反映する。
- 版番号をページの先頭に書く（例：IPL標準フロー v1.0）。
- バージョン管理（ライブラリのバージョン履歴）を有効にする。
- 「案件」ライブラリは、案件ごとに閲覧者を絞る。社外秘のヒアリング記録や未公開発明を、全社公開の場所に置かない。
- 発明塾の原資料（PDF・pptx）はこのサイトに置かない（利用条件の確認が済むまで。[docs/99_出典と改訂履歴.md](../docs/99_出典と改訂履歴.md) U1）。
- ページは「モダンページ」で作る。Copilot Studio はクラシックの ASPX ページの内容を回答に使わない（Microsoft Learn：https://learn.microsoft.com/microsoft-copilot-studio/knowledge-add-sharepoint ）。

## 3. エージェント用ナレッジのフォルダ

```text
/エージェント用ナレッジ
  IPL_00_全体像.docx
  IPL_Step0_何を決めるかを決める.docx
  …
  IPL_Step9_次に使えるように残す.docx
  IPL_90_発明塾手法との対応.docx
  IPL_ひな形集.docx
```

- 1ステップ1ファイルにする。見出し（手順 0-1 など）をそろえると、エージェントが該当箇所を探しやすくなる見込み（Copilot Studio の検索の仕組みに依存するため、テストで確かめる）。
- ファイル名を指定した質問（「IPL_Step3.docx には何と書いてある？」）は、SharePoint ナレッジでは答えられない、という制限が Microsoft のドキュメントに書かれている。ステップ番号や内容で質問する運用にする（M2）。

## 4. 公開までの手順

1. 社内レビュー（知財・事業企画・研究の各1名以上）で v1.0 を確定。
2. パイロット案件（2〜3件）で試し、目安時間とひな形を直す。
3. SharePoint ページとエージェント用ナレッジを作る。
4. Copilot Studio エージェントを作り、テスト質問で確かめる。
5. 動画を公開し、説明会を行う。
6. 3か月後に振り返り、v1.1 に改訂。
