# 子エージェントの設定ガイドとうまく動かないときの確認手順

> IPL標準フロー v1.1　対象：エージェント作成担当
> 2026-11-12 時点の調べ。Copilot Studio の画面や名称は変わることがあるため、作業前に Microsoft Learn の最新ページで確認すること（この資料の作成環境からは Microsoft Learn を直接開けず、検索結果の要約から整理している）。

## 1. まず押さえること：親は「説明（Description）」を読んで子を呼ぶ

生成オーケストレーション（Generative orchestration）を使うエージェントでは、親は子エージェントや接続エージェントの**名前と説明**を読んで、呼ぶかどうかを決める。説明があいまいだと呼ばれない、または呼ばれてほしくないときに呼ばれる（Microsoft Learn「Generative mode guidance」https://learn.microsoft.com/en-us/microsoft-copilot-studio/guidance/generative-mode-guidance 、FAQ https://learn.microsoft.com/en-us/microsoft-copilot-studio/faqs-generative-orchestration ）。

子エージェントの「指示（Instructions）」は、呼ばれた後の動き方を決めるもので、**呼ばれるかどうかには主に「説明」が効く**。この2つを混同しやすい。

## 2. 設定の確認リスト（上から順に）

| No | 確認すること | 場所（目安） | よくある状態 |
| --- | --- | --- | --- |
| 1 | 親エージェントで生成オーケストレーションがオンか | 親の設定 → Generative AI | クラシックのままだと子エージェントへの振り分けが働かない |
| 2 | 子エージェントの「説明」に、**いつ使うか**と**いつ使わないか**が具体的に書いてあるか | 子エージェントの詳細 | 「Web調査をする」だけでは短すぎる（3章の例） |
| 3 | 子エージェントの名前が、他のツール・トピックと紛らわしくないか | 同上 | 似た名前があると、説明で区別するしかない |
| 4 | 子エージェントに、検索先（公開サイトのナレッジ）や Web 検索が**子の側で**設定されているか | 子エージェントのナレッジ／設定 | 親にだけ設定して、子には何もない |
| 5 | 親の指示文に、子を呼ぶ条件が書いてあるか（説明と矛盾していないか） | 親の Instructions | 親の指示文で「Web検索は使わない」と書き、子も呼ばなくなる |
| 6 | 親のトピックが先に反応していないか | 親のトピック一覧 | 「調べて」などの言葉にトピックが反応し、子に回らない |
| 7 | （接続エージェントの場合）呼ばれる側が公開済みで、他のエージェントからの接続を許可しているか、同じ環境にあるか | 呼ばれる側の設定・公開 | 未公開、別の環境、権限がない |
| 8 | 子が終わった後に親へ戻る動きになっているか | 子の指示文 | 子が会話を続けて親に戻らない、何度も呼ばれる（ループ） |

## 3. 説明（Description）と指示文の書き方の例

### 子エージェント「Web調査」の説明（Description）の例

> 公開されている情報（特許公報、論文、公的機関の資料、決算資料、会社の発表）をインターネットで探し、出典URL付きで一覧にして返す。利用者が「調べて」「探して」「〜の情報が欲しい」と頼んだとき、または調査計画（STEP3）の行を渡されて情報を集めるときに使う。
> 使わない場面：IPL標準フローの手順・ひな形・用語の説明、シートの下書き、判断（Go/No Go）の相談、社外秘や出願前の発明の内容を含む依頼。これらは親エージェントが手順書をもとに答える。

ポイント：
- 「何をするか」「いつ使うか」「いつ使わないか」の3つを書く（使わない場面を書くと、呼ばれすぎを防げる）。
- 利用者が実際に使いそうな言い方（「調べて」「探して」）を入れる。
- 長くしすぎない。親が他の候補と見比べて選べる程度。

### 親の指示文に入れる対応（すでに [エージェント指示文.txt](エージェント指示文.txt) に記載）

- 調べものが必要なときは子エージェント「Web調査」を使う。手順の説明には使わない。
- 呼ぶ前に「確かめたい仮説ID」と「何を確かめたいか（1文）」をまとめて渡す。

### 子の指示文の最後に足す一文（親に戻らない・ループする場合）

> 調査結果を返したら、それ以上会話を続けず、親エージェントに戻る。追加の質問があっても、調査の依頼でなければ親エージェントに任せる。

## 4. うまく動かないときの確かめ方

### 4-1 アクティビティマップを見る

テスト画面で会話を試すと、親がどのツール・エージェントを候補にし、何を選んだかを「アクティビティマップ（Activity map）」で追える。まずここで、次のどれに当たるかを確かめる。

| 見えたこと | 考えられる原因 | 対応 |
| --- | --- | --- |
| 子エージェントが候補にも出ていない | 生成オーケストレーションがオフ／子が追加されていない・無効／トピックが先に反応 | 2章の1・6を確認 |
| 候補には出たが選ばれていない | 説明があいまい／他のツールの説明と重なる／親の指示文と矛盾 | 3章の形で説明を書き直す。親の指示文の矛盾を消す |
| 選ばれたがエラー・空の結果 | 子にナレッジや検索の設定がない／検索先のサイトがうまく引けていない／（接続の場合）公開・権限・環境 | 子を単独でテストし、子だけで答えられるか確かめる |
| 子が答えたが、親の回答が重複・言い換えになる | 親と子が両方とも答えを出している | 親の指示文に「子の結果はそのまま示し、言い換えない」と書く。利用者の報告では、指示文だけで完全には直らない例もある |
| 何度も子が呼ばれる・戻らない | 子の指示文に終わり方がない | 3章の「最後に足す一文」を入れる |

### 4-2 子エージェントを単独で試す

1. 子エージェントだけで「〇〇材料の市場の動きを公開情報で調べて」と聞き、出典付きで返るか確かめる。
2. 単独で動けば、問題は「親から呼ばれない（説明・振り分け）」側にある。
3. 単独でも動かなければ、子の設定（ナレッジ、検索、指示文）を直す。

### 4-3 切り分けのための最小構成

うまくいかない原因が分からないときは、いったん次の最小構成で試す。

- 親：指示文を短くする（子を呼ぶ条件だけ）。トピックは標準のものだけ。
- 子：説明は3章の例、ナレッジは公開サイト1つ（例：www.jpo.go.jp）だけ。
- これで呼ばれれば、元の構成で足したもの（指示文、トピック、ナレッジ）のどれかが邪魔をしている。1つずつ戻して確かめる。

## 5. 相談するときに用意してほしいもの

設定の相談をいただく場合、次があると原因を絞り込みやすい。

1. 親と子の「説明」「指示文」（貼り付け）
2. 試した質問と、実際の回答
3. アクティビティマップの画面（スクリーンショット）
4. 親の生成AIの設定画面（オーケストレーションの種類）
5. 子エージェントか接続エージェントか、どちらで作ったか
