## 作る順番（案）

1. Copilot Studio で新しいエージェントを作成し、名前・説明を入れる。
2. 「指示」に [エージェント指示文.txt](エージェント指示文.txt) を貼る。
3. ナレッジに SharePoint の「エージェント用ナレッジ」フォルダを追加する（[ナレッジ設計.md](ナレッジ設計.md)）。
4. 案内役の Web 検索はオフのままにし、子エージェント「Web調査」を追加する（[エージェント構成.md](エージェント構成.md)）。
5. 会話のスターターとトピックを設定する（[会話の入口とトピック.md](会話の入口とトピック.md)）。
6. [テスト質問.md](テスト質問.md) で確かめ、結果を記録する（フロー検証の V6：[../docs/92_フロー検証の進め方.md](../docs/92_フロー検証の進め方.md)）。
7. Teams または SharePoint に公開し、利用者を限定してパイロット運用する。

## 上限値などの注意（2026-11-10 時点で確認した範囲）

- 指示文の上限は 8,000 文字と Microsoft Learn の上限一覧に記載されている：https://learn.microsoft.com/en-us/microsoft-copilot-studio/requirements-quotas 。ただし、他の設定と合わせた内部の上限に当たる可能性があるとの報告もあり（Microsoft Q&A：https://learn.microsoft.com/en-gb/answers/questions/5874976/bug-character-limit-on-generative-answer-nodes ）、貼ったあとに動作を確かめる。
- SharePoint をナレッジにする手順・制限（モダンページのみ対応、ファイル名を指定した質問には答えられない など）：https://learn.microsoft.com/microsoft-copilot-studio/knowledge-add-sharepoint
- ファイルをアップロードしてナレッジにする場合の上限：https://learn.microsoft.com/microsoft-copilot-studio/knowledge-add-unstructured-data
- これらの値は改訂されることがあるため、公開前に再確認する。

## 運用上の注意（反証・見落としのリスク）

- 生成AIの回答は、ナレッジに書いてあっても誤って要約することがある。チェックポイントの判断や数字の根拠は、必ず元の文書と出典で確かめる運用にする。
- 指示文に「特許番号を作り出さない」と書いても、完全には防げない可能性がある。テスト質問 T08 で確かめ、STEP8 の「AIの間違い」に記録して指示文を直す。
- 発明塾の考え方をナレッジに入れることの可否は、利用条件の確認後に決める（[../docs/99_出典と改訂履歴.md](../docs/99_出典と改訂履歴.md) U1）。確認が済むまでは「90_発明塾手法との対応」をナレッジから外す選択肢もある。
- 利用者がエージェントに社外秘情報を入力する前提になるため、データの保存場所・保持期間・アクセス権について、情報システム部門の確認を受ける。
