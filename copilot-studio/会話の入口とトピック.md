# 会話の入口とトピック

## 1. 会話のスターター（画面に出す例文）

| 表示名 | 送られる文 |
| --- | --- |
| 新しい案件を始める | 新しいIPL案件を始めたい。依頼シートを一緒に作ってほしい。 |
| 今どのステップか確かめる | 案件ファイルを貼るので、今どのステップで、次に何をすればよいか教えてほしい。 |
| エッジ情報を整理する | 見つけた情報をエッジ情報カードにまとめたい。事実・解釈・将来の予想に分けてほしい。 |
| ファーストユーザーを決める | 顧客候補が3社ある。ファーストユーザーを決めるために何を調べればよいか教えてほしい。 |
| 外れている証拠を探す | この予想に反対の立場で、外れている証拠の候補と見落としを挙げてほしい。 |
| 判断メモを下書きする | 予想の記録を貼るので、判断メモの1枚目を下書きしてほしい。 |

## 2. トピックで固定化する流れ（生成AIの自由な回答に任せないもの）

| トピック | きっかけになる言葉の例 | 流れ |
| --- | --- | --- |
| 機密情報の確認 | 未公開、社外秘、出願前、NDA | 「社内規程で入力してよいか確認しましたか」と確認し、「はい」の場合のみ続ける。「いいえ」の場合は、伏せ字にする方法を案内する |
| FTOの相談 | 侵害、FTO、実施して大丈夫、訴えられる | 本フローはFTOを代替しないことを伝え、対象製品・国・時点を整理する項目だけを示し、知財部門・弁理士への相談を案内する |
| チェックポイント | チェック、通過、次に進んでいい？ | そのステップのチェックポイント（確認する人・確認すること・戻る先）を示し、確認した人と結果を案件ファイルに記録するよう伝える。通過の判断はしない |
| ひな形 | ひな形、テンプレート、シート | ステップを聞き、該当するひな形と SharePoint の場所を示す |

トピックの文言は、SharePoint のサイト名・窓口の部署名が決まってから入れる。

## 3. 返答の例（Step 2 の途中）

利用者：「顧客候補は A社・B社・C社。どこから聞きに行けばいい？」

期待する返答の形：

1. 次にやること（1つ）：手順2-3 のとおり、5項目（困りごとの強さ・頻度・今の手段への不満・予算と決裁権・接触できる可能性）で仮に評価してください。点数は聞きに行く順番を決めるためだけに使います。
2. 質問（3つまで）：各社で、実際に使う人と決裁者は分かっていますか／各社の今の代わりの手段は何ですか／接触の経路（発明者・共同研究先など）はありますか。
3. 外れている可能性：3社とも同じ業界の直接のお客様だけになっている場合、その先のお客様が困っていない可能性を見落とすおそれがあります。
4. 根拠：IPL_Step2 手順2-3、手順2-1。
